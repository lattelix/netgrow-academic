# Модульная структура NetGrow

## 1. Дерево модулей

```
src/
├── app/                          Маршруты Next.js App Router
│   ├── login/                    Экран 1: демо-вход и выбор роли
│   ├── (app)/                    Группа маршрутов, требующих сессии
│   │   ├── layout.tsx            Общая оболочка: шапка, навигация по ролям
│   │   ├── dashboard/            Экран 2: ролевой дашборд
│   │   ├── profile/              Экран 3: профиль и компетенции
│   │   ├── projects/             Экран 4-5, 9: каталог, карточка, редактор проекта
│   │   ├── teams/[id]/           Экран 6: рабочее пространство команды
│   │   ├── calendar/             Экран 7: календарь смены
│   │   ├── organizer/applications/ Экран 8: очередь заявок организатора
│   │   ├── analytics/            Экран 10: аналитика
│   │   └── admin/                Экран 11: администрирование справочников
│   ├── api/                      Route handlers — единственная точка мутаций
│   ├── error.tsx, not-found.tsx  Глобальные состояния ошибки/404
│   └── layout.tsx, globals.css   Корневой layout и тема оформления
├── components/
│   ├── ui/                       Безсостоятельные примитивы интерфейса
│   └── app/                      Компоненты навигации/сессии приложения
└── lib/
    ├── db/
    │   ├── schema.sql            Определение схемы PostgreSQL
    │   ├── client.ts             Singleton-подключение к базе
    │   ├── ids.ts                Генерация идентификаторов и меток времени
    │   ├── types.ts               Типы строк таблиц
    │   └── repo/                 Типизированные репозитории по сущностям
    ├── domain/                   Чистые бизнес-правила (без обращения к БД)
    ├── validation/schemas.ts     Zod-схемы для входных данных API
    ├── auth/session.ts           Работа с cookie сессии и текущим пользователем
    ├── api/respond.ts            Единый формат ответов/ошибок API
    └── format.ts                 Локализация дат и статусов (ru-RU)
scripts/                          CLI: инициализация, сид, сброс базы данных
e2e/                              Playwright-сценарии
```

## 2. Ответственность ключевых модулей

| Модуль | Ответственность | Не отвечает за |
| --- | --- | --- |
| `lib/db/repo/*` | SQL-запросы и преобразование строк в типизированные объекты | Проверку прав доступа и бизнес-правила |
| `lib/domain/eligibility.ts` | Проверка применимости заявки (статус проекта, возраст, дубликаты, вместимость) | Обращение к базе данных |
| `lib/domain/authorization.ts` | Проверка прав действия по роли и владению сущностью | HTTP-ответы, работу с сессией |
| `lib/domain/fit.ts` | Оценка соответствия компетенций участника требованиям проекта | Используется как вспомогательная метрика, не блокирует подачу заявки |
| `lib/auth/session.ts` | Чтение/запись cookie сессии, получение текущего пользователя | Проверку ролей (это делает `authorization.ts`) |
| `app/api/**/route.ts` | Оркестрация: сессия → авторизация → валидация → домен/репозиторий → журнал действий → ответ | Прямой рендеринг UI |
| `components/ui/*` | Переиспользуемые визуальные примитивы (кнопки, поля, состояния) | Бизнес-логику и обращение к API |

## 3. Правило зависимостей

Зависимости направлены сверху вниз: `app` → `domain`/`db` → нет обратных зависимостей.
Модули `lib/domain/*` не импортируют `lib/db/*` и не содержат побочных эффектов — это
позволяет тестировать их модульно без базы данных (см. `testing.md`).
