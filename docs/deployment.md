# Онлайн-редакция: GitHub, Vercel и PostgreSQL

## Версии

- `main`: онлайн-редакция Next.js с PostgreSQL. Данные не зависят от файловой системы приложения.
- `academic-sqlite`: сохранённая локальная редакция с SQLite для материалов ВКР.

В репозитории только учебное приложение и техническая документация. Документы ВКР,
подписи, договоры, локальные базы и секреты не публикуются.

## Локальный запуск и проверки

Требуются Node.js 20+, pnpm 10+ и PostgreSQL. Создайте базы `netgrow`, `netgrow_test`
и `netgrow_e2e`, скопируйте `.env.example` в `.env.local` и настройте локальные реквизиты.

```bash
pnpm install --frozen-lockfile
ALLOW_DB_RESET=1 pnpm db:reset
pnpm dev
pnpm typecheck
pnpm lint
pnpm test
pnpm e2e
```

Интеграционные тесты требуют отдельную локальную базу `netgrow_test`; e2e использует
только локальную `netgrow_e2e`. Проверка адреса выполняется до сброса данных и запрещает
облачные хосты и другие имена баз. Никогда не направляйте тесты в production.

## Vercel и Neon

1. Создайте проект Vercel из этого GitHub-репозитория, production-ветка `main`.
2. Выберите Next.js, Node.js 24, установку `pnpm install --frozen-lockfile`, сборку `pnpm build`.
3. Подключите через Vercel Marketplace отдельную базу Neon, выбрав план Free.
   Условия интеграции принимает владелец аккаунта. Платные планы не требуются для учебного стенда.
4. Проверьте, что интеграция передала `DATABASE_URL` в production. Это секрет;
   строка подключения не должна попасть в git, логи, скриншоты или переписку.
5. Один раз создайте схему командой `pnpm db:init` с production-переменными.
   Команда идемпотентна и не удаляет данные, но не является системой миграций будущих версий.
6. Убедитесь, что новая выделенная база пуста. Только для её первоначального заполнения
   запустите `pnpm db:seed` с `ALLOW_DB_RESET=1` и `ALLOW_REMOTE_DB_RESET=1`.
   Seed очищает таблицы: повторять его на используемой базе нельзя.
7. Запустите deployment из `main`, проверьте вход, роли и сохранение данных после повторного deployment.

Инициализация, seed и reset не включены в сборку. Новая публикация кода не должна сбрасывать
профили, заявки, команды и задачи. Предварительные публикации без отдельной базы не используйте
для разрушающих проверок. Схема production изменяется отдельной контролируемой операцией.

## Ограничения

Вход остаётся демонстрационным: посетители могут выбирать синтетические аккаунты, в том
числе администратора, и менять учебные данные. Это публичный стенд, а не сервис для реальных
людей. Не вводите персональные или закрытые сведения. Для настоящей эксплуатации необходимы
полноценная аутентификация, дополнительные ограничения запросов и стратегия резервного копирования.

Соблюдайте текущие лимиты бесплатных тарифов в панелях Vercel и Neon. Автоматическое подключение
платных тарифов этой инструкцией не предусмотрено.
