# Исправления независимого аудита от 02.10.2026

Область: PostgreSQL-редакция учебного NetGrow, ветка `agent/project-audit`.
Исходная ветка `academic-sqlite`, документы ВКР и production не изменялись.

## Подтверждённые проблемы и исправления

| Проблема | Исправление | Регрессия |
| --- | --- | --- |
| Анонимное чтение каталога и карточек через API | Сессия проверяется до выборки. Все вошедшие роли сохраняют доступ к каталогу | `read-access.test.ts`, `scoped-access.spec.ts` |
| Чтение полного списка пользователей и произвольного профиля | Список только для администратора; отдельный профиль для владельца и администратора | `authorization.test.ts`, `read-access.test.ts`, `scoped-access.spec.ts` |
| Глобальная аналитика организатора | Все агрегаты выводятся из его проектов; администратор сохраняет глобальные показатели | `scoped-reads.test.ts`, `scoped-access.spec.ts` |
| Глобальный журнал организатора | Фильтр по принадлежности сущности проекту, а не по автору действия; ограничение числа записей 1..100 | `scoped-reads.test.ts`, `scoped-access.spec.ts` |
| Разные права календаря в SSR и API | Один role-scoped репозиторий: общие события плюс команды участника или проекты организатора; администратор видит всё | `route.test.ts` для events, `scoped-reads.test.ts`, `scoped-access.spec.ts` |
| Изменение данных сохранялось при сбое журнала | Все бизнес-мутации с журналом обёрнуты в `withTransaction`; решение и отзыв заявки сохраняют существующую транзакцию | `audit-mutations.test.ts`, `decision-route.test.ts` |

Создание командного события дополнительно отклоняет несовпадение смены события со сменой проекта.
Частичный уникальный индекс активных заявок и порядок блокировок проекта/заявки сохранены.
Тест параллельной подачи подтверждает один ответ 201, один 409, одну заявку и одну запись журнала.

Дополнительная рецензия перед merge выявила и исправила ещё два инварианта:
- конкурентные PATCH одной задачи больше не затирают изменения разных полей: обновление выполняется как настоящий partial SQL update под `FOR UPDATE`;
- вместимость проекта нельзя уменьшить ниже уже сформированного состава команды, причём проверка использует тот же project lock, что и одобрение заявок.

Сквозной сценарий защиты дополнен фактической сменой статуса назначенной задачи участником и последующей проверкой dashboard/analytics.

Эти проверки не заменяют нагрузочный тест или профессиональный security-аудит.

## Ограничения и связь с ВКР

Демо-вход остаётся публичным выбором синтетической роли, включая администратора.
Исправления разграничивают действия внутри выбранной роли, но не обеспечивают
проверку личности посетителя. Реальные данные вводить нельзя.

Проверена локальная production-сборка с PostgreSQL, а не опубликованный облачный сервис.
Подключение Neon и реальный запуск Vercel остаются отдельным этапом.

Исправления не переносились автоматически в SQLite-редакцию. Ссылаться в тексте ВКР
на эти результаты как на проверку исходной SQLite-версии нельзя. При выборе её для
защиты требуется отдельный перенос соответствующих исправлений и новый прогон.
