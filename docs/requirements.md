# Требования к системе NetGrow

Идентификаторы требований используются в `testing.md` для трассировки на тесты.

## 1. Функциональные требования

| ID | Требование | Реализация |
| --- | --- | --- |
| ФТ-01 | Демонстрационный вход с выбором роли (участник/организатор/администратор) | `src/app/login`, `POST /api/session` |
| ФТ-02 | Ведение профиля компетенций участника (добавление, изменение уровня, удаление) | `src/app/(app)/profile`, `PUT/DELETE /api/profile/competencies` |
| ФТ-03 | Каталог проектов с фильтрами по направлению, компетенциям, возрастной группе и статусу | `src/app/(app)/projects`, `GET /api/projects` |
| ФТ-04 | Просмотр карточки проекта и требуемых компетенций | `src/app/(app)/projects/[id]` |
| ФТ-05 | Подача заявки на проект с проверкой применимости | `POST /api/applications`, `src/lib/domain/eligibility.ts` |
| ФТ-06 | Запрет дублирующей активной заявки на один проект | Частичный уникальный индекс `uq_applications_active` + доменная проверка |
| ФТ-07 | Отзыв собственной заявки в статусе «на рассмотрении» | `DELETE /api/applications/[id]` |
| ФТ-08 | Очередь заявок организатора с фильтром по статусу | `src/app/(app)/organizer/applications` |
| ФТ-09 | Одобрение/отклонение заявки с проверкой прав и вместимости команды | `PATCH /api/applications/[id]` |
| ФТ-10 | Автоматическое формирование/пополнение команды при одобрении заявки | `getOrCreateTeam` + `addTeamMember` в обработчике решения по заявке |
| ФТ-11 | Создание и редактирование проекта организатором/администратором | `src/app/(app)/projects/new`, `.../[id]/edit`, `POST/PATCH /api/projects` |
| ФТ-12 | Рабочее пространство команды: список участников и задач | `src/app/(app)/teams/[id]` |
| ФТ-13 | Создание задачи и назначение исполнителя из состава команды | `POST /api/teams/[id]/tasks` |
| ФТ-14 | Изменение статуса задачи исполнителем или организатором | `PATCH /api/tasks/[id]` |
| ФТ-15 | Календарь мероприятий смены (общих и по командам) | `src/app/(app)/calendar`, `GET/POST /api/events` |
| ФТ-16 | Аналитика: проекты/заявки/задачи по статусам, заполненность команд, среднее время решения | `src/app/(app)/analytics`, `GET /api/analytics` |
| ФТ-17 | Администрирование смен, справочника компетенций и ролей пользователей | `src/app/(app)/admin` |
| ФТ-18 | Журнал важных мутаций (заявки, задачи, проекты, роли) | `src/lib/db/repo/activityLog.ts`, вызывается из всех мутирующих обработчиков |
| ФТ-19 | Печатная/экспортная сводка по проекту | Кнопка печати на `src/app/(app)/projects/[id]/PrintButton.tsx` (печатная стилизация страницы) |
| ФТ-20 | Детерминированные команды инициализации и сброса демо-данных | `pnpm db:init`, `pnpm db:seed`, `pnpm db:reset` |

## 2. Нефункциональные требования

| ID | Требование | Реализация / подтверждение |
| --- | --- | --- |
| НФТ-01 | Адаптивность от 360 px до десктопа | Tailwind-раскладка (`flex-wrap`, `grid`, относительные единицы) во всех экранах |
| НФТ-02 | Клавиатурная доступность и видимый фокус | `:focus-visible` в `globals.css`, семантические `button`/`a`, отсутствие кликабельных `div` |
| НФТ-03 | Семантическая разметка и подписи форм | `label`/`fieldset`/`legend`, `aria-live`/`role="alert"` для ошибок, `role="status"` для загрузки |
| НФТ-04 | Отсутствие внешних сетевых зависимостей во время демонстрации | Все шрифты и стили — системные/локальные; локальная SQLite |
| НФТ-05 | Детерминированный локальный запуск | `README.md`, `docs/demo-script.md` |
| НФТ-06 | Отсутствие секретов в репозитории | `.gitignore` исключает `data/*.db`, `.env*`; демо-вход без паролей |
| НФТ-07 | Централизованная обработка ошибок API и валидация входа | `src/lib/api/respond.ts`, `src/lib/validation/schemas.ts` |
| НФТ-08 | Безопасные настройки cookie для локальной демонстрации и рекомендации для production | `src/lib/auth/session.ts`, `docs/security.md` |
| НФТ-09 | Логирование без персональных и секретных данных | `activity_log` хранит только идентификаторы и синтетические имена |
| НФТ-10 | Строгий режим TypeScript | `tsconfig.json` (`"strict": true`), `pnpm typecheck` без ошибок |

## 3. Роли и разрешения (сводно)

Подробная матрица авторизации — в `security.md`. Кратко:

- **Участник**: профиль, каталог, заявки на себя, задачи, где назначен, календарь.
- **Организатор**: всё из роли участника (для чтения) + создание/редактирование своих
  проектов, решения по заявкам своих проектов, задачи в своих командах, аналитика.
- **Администратор**: все действия организатора над любым проектом + справочники
  (компетенции, смены) + управление ролями пользователей.
