# Журнал прогресса разработки NetGrow

## 01.10.2026: отдельная онлайн-редакция

По разрешению владельца подготовлен публичный учебный репозиторий. Исходная SQLite-редакция
сохранена в ветке `academic-sqlite`; `main` использует PostgreSQL. Материалы ВКР,
документы практики, подписи и локальные базы не публикуются.

Репозитории и обработчики переведены на асинхронный `pg`. Решение по заявке использует
один transaction client и блокировку проекта для проверки вместимости. Фильтр смены
в API календаря теперь только сужает набор доступных событий. Сбросы баз защищены
явным разрешением; тесты допускают только отдельные локальные базы.

Проверки: 48 тестов в 8 файлах, typecheck, lint и production-сборка успешны;
10 сквозных сценариев Playwright пройдены. Дополнительно проверены 13 страниц для
трёх ролей на desktop/mobile без ошибок страниц и переполнения.

Проект Vercel подготовлен. Создание Neon Free требует принятия условий интеграции
владельцем аккаунта; до этого облачный запуск и сохранность после cloud deployment
не подтверждены. Инструкции: `deployment.md`.

Ниже сохранена история исходной локальной редакции.

Формат: дата/этап, что сделано, какие команды выполнялись и их фактический результат,
что осталось, известные блокеры. Записи не переписывают историю — только дополняются.

## Этап 0 — Планирование

Прочитаны `AGENTS.md` и `PROJECT_BRIEF.md`. Принят план: сначала данные и домен (схема

## Этап 1 — Инфраструктура и данные

- Инициализирован Next.js 16 (App Router, TypeScript strict, Tailwind 4, ESLint) через
  `pnpm dlx create-next-app@latest`.
- Установлены `better-sqlite3`, `zod`, `lucide-react`, `vitest`, `@testing-library/*`,
  `@playwright/test`, `tsx`.
- **Блокер и решение**: `better-sqlite3@13` вызывал сегфолт (`exit code 139`) при
  создании подключения в этом окружении (несовместимость нативного prebuild-бинаря с
  Node 20.20.2 в песочнице). Решение: понижена версия до `better-sqlite3@11.10.0` и
  добавлен `node-gyp@10` как dev-зависимость, чтобы `pnpm install` мог собрать нативный
  модуль из исходников через `prebuild-install || node-gyp rebuild --release`, если
  бинарный prebuild недоступен по сети. После этого `pnpm install` и `pnpm db:reset`
  проходят стабильно и воспроизводимо.
- Спроектирована и реализована схема SQLite (`src/lib/db/schema.sql`) со всеми сущностями
  из брифа, внешними ключами, индексами и частичным уникальным индексом, запрещающим
  дублирующиеся активные заявки.
- Реализован типизированный слой доступа к данным (`src/lib/db/repo/*`).
- Написан детерминированный сид демо-данных на синтетическом русском языке
  (`scripts/seed.ts`): 1 администратор, 2 организатора, 12 участников, 16 компетенций,
  7 проектов разных статусов, заявки в разных состояниях, 4 сформированные команды,
  8 задач, 6 событий смены.
- Команды `pnpm db:init`, `pnpm db:seed`, `pnpm db:reset` выполнены многократно, результат
  стабилен и повторяем.

## Этап 2 — Домен, авторизация, API

- Реализованы чистые доменные модули: `eligibility.ts` (применимость заявки),

  ошибок (`src/lib/api/respond.ts`).
- `pnpm typecheck` пройден без ошибок после реализации API-слоя.

- Ручная проверка сквозного сценария через `curl` с реальными cookie-сессиями:
  вход участником → подача заявки → вход организатором → одобрение → создание команды →
  назначение задачи → проверка запрещённых действий (403 для участника, пытающегося
  одобрить заявку или создать проект). Все проверки прошли успешно.
- `pnpm build` пройден успешно, сгенерированы все маршруты.

## Этап 4 — Тесты

- Настроен Vitest (`vitest.config.mts`, jsdom-окружение, alias `@/*`).
  **Блокер и решение**: `jsdom@30` вызывал ошибку `webidl.util.markAsUncloneable is not a
  function` при старте воркеров под Node 20 (несовместимость версии с Node 20 в этом
  окружении). Решение: понижена версия до `jsdom@25`.
  Также добавлен ручной вызов `cleanup()` в `afterEach` (`vitest.setup.ts`), так как без
  включённых `globals: true` автоматическая очистка DOM между тестами `@testing-library/react`
  не срабатывает.
- Написаны и пройдены модульные тесты домена: `eligibility.test.ts`, `fit.test.ts`,
  `authorization.test.ts`, а также компонентные тесты `States.test.tsx`, `Button.test.tsx`.
  `pnpm test` → 5 файлов, 26 тестов, все пройдены.
- Настроен Playwright (`playwright.config.ts`) с изолированной базой данных для
  e2e-прогона (`NETGROW_DB_PATH=./data/netgrow.e2e.db`, пересоздаётся в
  `e2e/global-setup.ts`) и сборкой/запуском production-сервера на порту 3100.
  **Блокер и решение**: `pnpm start -- -p 3100` некорректно передавал аргументы через
  pnpm-скрипт (next получал `-p` как путь к проекту). Решение: команда веб-сервера в
  конфиге заменена на `pnpm build && pnpm exec next start -p 3100`.
- Написаны и пройдены сценарии `e2e/defense-workflow.spec.ts` (полный сценарий защиты в
  4 шага) и `e2e/forbidden-mutation.spec.ts` (6 независимых запрещённых сценариев, включая
  проверку того, что организатор не видит заявки к чужим проектам, и того, что посторонний
  авторизованный пользователь не получает данные чужой команды через API).
  `pnpm e2e` → 10 из 10 тестов пройдены.
