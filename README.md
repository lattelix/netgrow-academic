# NetGrow — информационная система лагеря

Учебное веб-приложение для выпускной квалификационной работы «Проектирование и разработка
информационной системы на примере социальной платформы NetGrow». Автоматизирует формирование
проектных команд и координацию образовательной деятельности в условном детском
оздоровительном лагере ООО «Дружба». Это самостоятельная реализация: код, данные, роли и
метрики синтетические и не связаны с какими-либо реальными коммерческими продуктами.

## Стек

Next.js 16 (App Router) · React 19 · TypeScript (strict) · Tailwind CSS 4 · lucide-react ·
PostgreSQL (pg / node-postgres) · Zod · Vitest + Testing Library · Playwright · pnpm

Это редакция с постоянным хранилищем PostgreSQL вместо локального файла SQLite — подробнее
в разделе [«Развёртывание»](#развёртывание) ниже.

## Установка и запуск (с нуля)

Требуется Node.js 20+, pnpm 10+ и локальный сервер PostgreSQL (установленный отдельно, не
входит в зависимости проекта).

```bash
pnpm install                                    # установка зависимостей
cp .env.example .env.local                      # указать строку подключения к PostgreSQL
createdb netgrow                                # создать локальную базу данных (один раз)
DATABASE_URL=postgresql://localhost/netgrow \
  ALLOW_DB_RESET=1 pnpm db:reset                 # создать схему и загрузить демо-данные
pnpm dev                                        # http://localhost:3000
```

`.env.local` не попадает в git (см. `.gitignore`). Строка подключения может содержать
пароль: не публикуйте её. Локальные параметры зависят от настроек вашего PostgreSQL.

Открыть [http://localhost:3000](http://localhost:3000) — система перенаправит на экран
входа. Вход демонстрационный, без пароля: выберите один из синтетических аккаунтов.

### Сброс данных в любой момент

```bash
ALLOW_DB_RESET=1 pnpm db:reset
```

Полностью и детерминированно пересоздаёт схему и данные в базе, указанной в `DATABASE_URL`
(те же пользователи, проекты, заявки и задачи при каждом запуске). `ALLOW_DB_RESET=1`
обязателен — это разрушительная операция, и она никогда не выполняется автоматически при
сборке или развёртывании. Для базы на внешнем хосте (не localhost) дополнительно требуется
`ALLOW_REMOTE_DB_RESET=1`.

## Скрипты

| Команда | Назначение |
| --- | --- |
| `pnpm dev` | Запуск сервера разработки |
| `pnpm build` | Production-сборка |
| `pnpm start` | Запуск production-сборки |
| `pnpm lint` | ESLint |
| `pnpm typecheck` | Проверка типов (`tsc --noEmit`) |
| `pnpm test` | Модульные и компонентные тесты (Vitest); требует `TEST_DATABASE_URL` для интеграционных тестов на реальном PostgreSQL |
| `pnpm test:watch` | Тесты в режиме наблюдения |
| `pnpm e2e` | Сквозные тесты (Playwright); поднимает production-сборку и сбрасывает отдельную БД `netgrow_e2e` перед прогоном |
| `pnpm db:init` | Создать схему БД без загрузки данных (идемпотентно, `CREATE TABLE IF NOT EXISTS`) |
| `pnpm db:seed` | Загрузить детерминированные демо-данные (не удаляя схему); требует `ALLOW_DB_RESET=1` |
| `pnpm db:reset` | Полный сброс: удалить таблицы → создать схему → загрузить демо-данные; требует `ALLOW_DB_RESET=1` |

`pnpm test` ожидает отдельную базу `TEST_DATABASE_URL` (например
`postgresql://localhost/netgrow_test`, создать заранее через `createdb netgrow_test`) — тесты
сами создают схему и сбрасывают данные между проверками, но никогда не трогают
`DATABASE_URL`. Без `TEST_DATABASE_URL` интеграционные тесты в
`src/lib/domain/__tests__/decision-route.test.ts` и `src/app/api/events/__tests__/route.test.ts`
завершатся понятной ошибкой с инструкцией, а не молча пропустятся.

## Архитектура (кратко)

Next.js App Router с тремя слоями: серверные/клиентские компоненты (`src/app`, `src/components`),
route handlers как единственная точка мутаций с Zod-валидацией и проверкой прав
(`src/app/api`), доменный слой чистых бизнес-правил (`src/lib/domain`) и типизированный
слой доступа к PostgreSQL (`src/lib/db`, параметризованный SQL через `pg`, без ORM).
Подробности, C4-диаграммы и границы безопасности — в
[`docs/architecture.md`](docs/architecture.md).

Роли: **участник** (профиль, каталог, заявки, задачи, календарь), **организатор**
(проекты, очередь заявок, команды, задачи, аналитика — в рамках своих проектов),
**администратор** (всё из роли организатора над любым проектом + справочники и роли
пользователей). Авторизация мутаций всегда проверяется на сервере независимо от того, что
показывает интерфейс — матрица прав в [`docs/security.md`](docs/security.md).

## Развёртывание

Эта редакция рассчитана на публикацию в интернете: приложение размещается на **Vercel**, а
постоянное хранилище — **PostgreSQL на Neon**. Схема и локальный доступ к данным не меняются
между окружениями — отличается только строка подключения (`DATABASE_URL`), которую платформа
хостинга передаёт как переменную окружения. Эта веб-редакция хранит данные иначе, чем текущая
версия выпускной работы (там используется локальный файл SQLite) — она не заменяет и не
изменяет материалы ВКР: файлы работы, презентация и лист с подписью в этот репозиторий не
входят и не создаются отсюда. Оригинальная SQLite-версия для защиты сохранена в ветке
[`academic-sqlite`](https://github.com/lattelix/netgrow-academic/tree/academic-sqlite).
Порядок настройки описан в [`docs/deployment.md`](docs/deployment.md).

Публикация и развёртывание (включая `git push`, создание облачных ресурсов и подключение
`.vercel`) выполняются только с явного разрешения пользователя на конкретное действие — см.
[`AGENTS.md`](AGENTS.md).

## Демонстрационная аутентификация

Вход в систему — осознанно упрощённый учебный механизм: пользователь выбирает один из заранее
подготовленных **синтетических** аккаунтов на экране входа, без пароля. Это не реальные люди и
не секреты — email-адреса вида `*@druzhba.demo` и соответствующие им роли созданы специально
для демонстрации и воспроизводятся каждым запуском `pnpm db:seed`. Production-рекомендации по
полноценной аутентификации — в [`docs/security.md`](docs/security.md).

## Ограничения демонстрационной версии

- Аутентификация упрощена до выбора демо-аккаунта без пароля (см. выше).
- Внешние интеграции (уведомления, почта, файловое хранилище) не реализованы — вне рамок
  задания.
- Резервное копирование не требуется для демо-данных: состояние полностью восстанавливается
  командой `ALLOW_DB_RESET=1 pnpm db:reset`.
